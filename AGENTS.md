# AGENTS.md

## Project Overview

This is a Hexlet DevOps learning project. The actual app (JS Fastify Blog) lives in `app/` and is cloned from `github.com/hexlet-components/js-fastify-blog`. The root of this repo contains Docker infrastructure only — no app code.

## Key Commands

```bash
make setup   # Install deps + run DB migrations (one-time)
make dev     # Start dev server at http://127.0.0.1:8080
make test    # Run tests via Docker Compose (CI mode)
make ci      # CI mode: same as test, used by GitHub Actions
make build   # Build production image from Dockerfile.production
make push    # Push production image to Docker Hub
```

## Docker Compose Two-File Pattern

- `docker-compose.yml` — production/test config. Default command: `make test`. No port exposed.
- `docker-compose.override.yml` — auto-merged for local dev. Adds port `8080:8080` and overrides command to `make dev`.

**Critical:** To run tests, you MUST use `-f docker-compose.yml` to exclude the override:
```bash
docker-compose -f docker-compose.yml up --abort-on-container-exit --exit-code-from app
```
Without `-f`, Compose merges both files and runs dev mode instead of tests.

## Volume Mounting

- `./app:/app` — the app directory is mounted into the container. Code edits on the host are reflected inside.
- `node_modules` is excluded via `.dockerignore` and installed fresh inside the container.
- Files created inside the container as root will be owned by root on the host. Use `-u $(id -u):$(id -g)` flag if needed.

## Dockerfile

Minimal — only sets base image (`node:20.12.2`) and `WORKDIR /app`. All logic (install, test, dev) is in `app/Makefile`.

## App Structure (inside `app/`)

- `server/` — Fastify backend (routes, views in Pug, DB models via Sequelize)
- `src/` — frontend source (webpack builds to `dist/`)
- `database.sqlite` — SQLite database (do not commit)
- `app/Makefile` — all app-level commands: `setup`, `dev`, `test`, `lint`, `build`
- `app/package.json` — Fastify + Sequelize + Jest + Pug + Webpack

## Testing

- Tests run via `NODE_ENV=test npm test -s` (Jest, single-threaded `--runInBand`)
- `pretest` hook resets and re-runs DB migrations before each test run
- DB: SQLite with Sequelize ORM

## CI

- `.github/workflows/hexlet-check.yml` — auto-generated, runs Hexlet project check on every push
- Do not edit this file
- `.github/workflows/push.yml` — CI workflow on push to `main`:
  1. Runs tests via `make ci` (Docker Compose with `-f docker-compose.yml`)
  2. On success: builds `Dockerfile.production` and pushes to Docker Hub with `latest` tag
  3. Uses `docker/login-action`, `docker/setup-buildx-action`, `docker/build-push-action`
  4. Requires `vars.DOCKERHUB_USERNAME` and `secrets.DOCKERHUB_TOKEN` in repo settings
